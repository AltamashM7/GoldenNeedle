# Decision log

These decisions describe the current product and architecture direction. A later Orchestrator instruction may explicitly change an **OPEN / MAY CHANGE** item.

| Decision | Status | Rationale |
|---|---|---|
| Unity 6.5 | **LOCKED** | Establishes the engine baseline for SIH 2026 development and avoids version drift. |
| URP | **LOCKED** | Provides the current Unity rendering baseline while supporting a deliberately simple, CPU-conscious presentation target. |
| CPU-first / no required dedicated GPU | **LOCKED** | The application must run acceptably on an ordinary computer without requiring a discrete GPU. |
| Camera experience integrated into Unity | **LOCKED** | The user-facing product must provide one cohesive application rather than require an external tracking program. |
| MediaPipe Pose Landmarker | **PLANNED V1 / replaceable implementation** | It is the current local single-person pose-tracking direction, but the provider boundary protects the project from backend changes. |
| Full-body digital embodiment, not merely gesture-triggered buttons | **LOCKED PRODUCT DIRECTION** | Continuous body-driven avatar control is the core innovation and fitness interaction model. |
| Engine-owned canonical skeleton | **LOCKED ARCHITECTURAL DIRECTION** | Downstream systems need a stable project-owned body representation independent of provider-specific results. |
| Pose and locomotion are separate systems | **LOCKED ARCHITECTURAL DIRECTION** | Body reproduction and conversion of actions such as jogging in place into world movement have different semantics and tuning needs. |
| Modular Hub/course structure | **LOCKED ARCHITECTURAL DIRECTION** | Independent environments and courses reduce coupling and support parallel content ownership. |
| Git LFS enabled from initial repository setup | **CURRENT REPOSITORY DECISION** | The local Git LFS client and repository filters/endpoint are present; current `.gitattributes` has no LFS-managed patterns, so this state is preserved and reported rather than expanded speculatively. |
| GitHub Desktop for user's normal Git operations | **CURRENT WORKFLOW DECISION** | The USER uses GitHub Desktop for normal branch, commit, push, and PR-related mutations. |
| Web Sol Orchestrator + Codex Luna local Builder | **CURRENT DEVELOPMENT WORKFLOW** | Separates architecture/integration review from local implementation and verification. |
| Official Unity Codex plugin `unity@unity-agent-plugin` | **CURRENT DEVELOPMENT TOOLING DECISION** | Provides Unity-specific Codex skills through the first-party Unity Technologies integration; it remains outside the Golden Needle runtime. |
| Official Unity CLI + Pipeline package `com.unity.pipeline` `0.5.0-exp.1` + Unity MCP | **CURRENT DEVELOPMENT TOOLING DECISION** | Gives Codex a supported path to inspect and perform harmless operations in the live Unity Editor while keeping the integration out of shipped product dependencies. |
| Integrated laptop webcam is a supported baseline input | **LOCKED SPIKE REQUIREMENT** | The first technical spike must work with an ordinary built-in webcam; external or depth hardware is optional. |
| Partial-body tracking is valid | **LOCKED SPIKE REQUIREMENT** | Upper-body control data remains usable when legs are outside the frame; trust is evaluated per landmark and missing lower-body landmarks do not reject the whole pose. |
| MediaPipeUnityPlugin `0.16.3` embedded CPU runtime + local Pose Landmarker Lite model | **CURRENT SPIKE IMPLEMENTATION** | Repository-portable local model, one pose, CPU inference, segmentation disabled. The provider boundary keeps this replaceable. |
| Bounded latest-frame camera preparation | **IMPLEMENTED / AWAITING USER QA** | At most one AsyncGPUReadback, one replaceable prepared TextureFrame and one MediaPipe inference may exist. Readback may overlap inference; newer prepared work replaces older prepared work. There is no historical frame queue, inference backlog or cadence catch-up. |
| Motion Engine long-lived phase branch | **CURRENT WORKFLOW DECISION** | `engine/pose-tracking-spike` carries core Motion Engine phases through the Phase 6 graybox checkpoint. Each phase follows implementation -> USER QA -> accepted checkpoint -> audit; intermediate checkpoints are not mechanically merged into `main`. |
| Phase 2 canonical joint set and partial validity | **CURRENT PHASE 2 IMPLEMENTATION** | Engine-owned frame contains the 20 named canonical joints plus trusted midpoint derivations; missing joints do not invalidate the whole frame. |
| Phase 2 canonical coordinates | **CURRENT PHASE 2 IMPLEMENTATION** | Image x increases right and y increases up. Canonical 3D uses +X camera/view right, +Y up, +Z away. Conversion occurs once at the provider-to-canonical boundary. |
| Single canonical camera / inference frame | **PHASE 4 USER ACCEPTED** | Front-facing status does not request horizontal inference mirroring; vertical/rotation transport remains. Display mirror is presentation-only and canonical normalized/world mapping is unchanged. |
| Phase 4 signed canonical-to-avatar mapping | **PHASE 4 USER ACCEPTED** | Corrected frontal source semantics are `R≈-X, U≈+Y, F≈-Z`; the accepted signed reference mapping drives procedural and Animator Humanoid paths. |
| Phase 4 positional limb retargeting + analytic IK | **PHASE 4 USER ACCEPTED** | Stabilized normalized limb targets map through the accepted reference basis and preserve avatar-authored proportions; project-owned analytic two-bone IK remains authoritative. |
| Phase 4 modular measurement calibration | **PHASE 4 USER ACCEPTED** | Comfortable body reference establishes torso axes/proportions and each limb chain accumulates independent measurements; missing limbs do not globally block motion. |
| Phase 5A hybrid locomotion | **IMPLEMENTED / NOT USER ACCEPTED** | Finite support-foot camera-space displacement and cadence extension are fused while Phase 4 pose reproduction stays separate. Acceptance QA is paused while lower-level motion response is hardened. |
| Phase 5A root estimation | **IMPLEMENTED / AWAITING USER QA** | Physical translation authority is the ankle/heel/toe support-base model. Torso apparent scale is auxiliary depth corroboration only. |
| Phase 5A cadence fusion | **IMPLEMENTED / AWAITING USER QA** | Cadence extends range only when rhythmic lower-body stepping exists and meaningful physical root velocity is small; physical motion suppresses cadence to avoid obvious double-counting. |
| Phase 5A recenter | **IMPLEMENTED / AWAITING USER QA** | Public `Recenter()` makes the current physical location the new tracking origin while preserving current virtual X/Z. |
| Phase 5A vertical/root authority | **LOCKED PROTOTYPE RULE** | Locomotion writes avatar-root X/Z only; root Y and rotation remain excluded. |
| Phase 5A physical coordinate mapping | **IMPLEMENTED / AWAITING USER QA** | Camera-space physical displacement is scaled then mapped through the accepted Phase 4 reference canonical-to-avatar axis map before world X/Z application. Live body heading affects cadence only. |
| Phase 5A physical scale defaults | **FIRST-QA TUNING DECISION** | Current lateral/depth defaults are `0.9 / 1.5`; they remain Inspector-tunable rather than production-locked. |
| Phase 5A support model v3 | **IMPLEMENTED / AWAITING USER QA** | Common `(L+R)/2` support displacement drives room movement while differential `(L-R)/2` gait evidence attenuates depth trust. |
| Phase 5A F12 Lab/Game mode | **IMPLEMENTED / AWAITING USER QA** | F12 is presentation-only. Lab keeps webcam/debug IMGUI; Game hides IMGUI and uses the persistent third-person camera. Engine behavior is unchanged. |
| Sustainable MediaPipe scheduler | **IMPLEMENTED / AWAITING USER QA** | Target 30 FPS is a maximum. Request timing is anchored to accepted DetectAsync calls; there is still exactly one outstanding inference and no catch-up queue. Readback preparation is now decoupled from inference occupancy to remove proven serialized dead time. |
| Humanoid render-rate presentation smoothing | **IMPLEMENTED / AWAITING USER QA** | Exact Phase 4 solve remains authoritative. Visible rotations converge toward only the newest target with defaults 45/s response and 50 ms max blend; no delayed pose buffer exists. |
| Tracking vs presentation data | **LOCKED BOUNDARY** | Phase 5A consumes genuine stabilized tracking data; smoothed avatar rotations are presentation-only. |
| External/phone camera selection | **IMPLEMENTED / AWAITING USER QA** | Persist WebCamDevice name; Inspector enumerates devices and V cycles ordinary devices. Phones require OS/UVC/virtual-webcam exposure; no phone-specific network protocol exists. |
| Manual camera rotation | **IMPLEMENTED / AWAITING USER QA** | Auto follows `videoRotationAngle`; optional 0/90/180/270 overrides drive inference preparation and Lab display/convention state. Front-facing metadata still does not imply H inference mirror. |
| Camera hot-switch safety | **IMPLEMENTED / AWAITING USER QA** | Pending switch blocks new old-camera work, waits for active readback/inference, restarts one provider pipeline, bumps source/session convention version, and invalidates calibration/Phase 5A origin assumptions. |
| Pose target cadence 30 FPS | **CURRENT PROTOTYPE DEFAULT** | 30 FPS is requested maximum cadence, not a result-rate guarantee; actual result rate remains hardware/CPU constrained. |
| Pipeline timing diagnostics | **IMPLEMENTED / AWAITING USER QA** | F7 exposes rolling capture/render/request/result data plus observed readback completion, CPU image-build, DetectAsync callback and approximate Unity-observed frame-to-result timing, with separate wait/failure reasons and no per-frame log spam. |
| Lab clear-only camera | **IMPLEMENTED / AWAITING USER QA** | In Lab, the persistent Camera remains enabled with culling mask zero and solid-color clear so Unity does not show `No cameras rendering`, while IMGUI retains fitted whole-frame webcam geometry. F12 restores the original world render settings. |
